AGENT TECHNICAL DESCRIPTION — Agent 247

Operator:                PayRail Ltd (licence PSP-4471)
Agent name:              Agent 247
Agent identifier:        payrail-agent-247
Software:                RailPay AP Agent, version 2.4.0
Purpose:                 read supplier invoices for PayRail's business customers and initiate
                         payment instructions to the customer's bank, within a customer-signed mandate

Model documentation
  Model provider:        Anthropic (Claude), accessed through the RailPay orchestration layer
  Model version:         claude-sonnet-5 (pinned; changes require re-registration)
  Benchmarks:            invoice field extraction 99.2% exact match on the RailPay AP-2026 test
                         set (1,200 invoices); payee-change detection 100% recall on 300 seeded
                         redirection attempts
  Training type:         foundation model, no fine-tuning; retrieval and tool use only; no
                         customer data used for training

Requested authority
  Action type:           pay_invoice (initiate a payment to an allowlisted supplier account)
  Customers:             none named. Each customer writes and signs its own mandate within the
                         authority's policy ceilings
  Human confirmation:    PayRail proposes that instructions above GBP 5,000 are held for
                         confirmation by the customer's authorising officer

Configuration
  Configuration file:    agent_config.json
  SHA-256:               3461e119a630aec53b47b3cc7777d99b1fcfb89c03a075938519896148df628b
  The configuration file fixes the permitted action, the payee source (mandate allowlist only)
  and the escalation route. Any change produces a new hash and a fresh application.

Key management
  Signing algorithm:     Ed25519
  Public key:            bound at application through the authority's signed-challenge step
  Private key storage:   hardware-backed key store in PayRail's deployment; not exportable
  Key rotation:          every 12 months, or immediately on suspected compromise, with
                         re-registration of the new public key

Logging
